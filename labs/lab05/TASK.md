# ЛР5. Переданный построитель отчёта

Вариант: **Reporting**.

## Что дано

Сервис создаёт свой построитель истории и использует общий список строк между вызовами. Основной метод `ReportingService.build()` также нужно реализовать; готовые проверки объектов и зависимостей не переписывайте.

## Задание

### Шаг 1. Сохраните зависимости и настройте сборку

В `ReportingService(repository, builder)` используйте переданную реализацию. Создание стандартного объекта перенесите в `build_service()`.

Временные строки создавайте внутри вызова. Каждый `Report` должен получить собственный `tuple`, не накапливая строки предыдущего отчёта.

### Шаг 2. Реализуйте `ReportingService.build()`

Проверьте код валюты, передайте текущие записи выбранному `builder.build(records, code)`, затем вызовите `validate_report(result, code)`. Не подменяйте результат другим отчётом.

### Шаг 3. Проверьте отказ и следующий вызов

Контрольный исполнитель сначала выбрасывает `DomainError("TEMPORARY")`, затем успешно работает. Первый вызов не повторяется автоматически и не меняет данные; второй использует того же исполнителя. `TEMPORARY` — код учебной проверки, не новая ветка бизнес-логики. Отсутствие зависимости проверяйте через `is None`, а не её истинность.

### Шаг 4. Обязательная практическая часть

В `ReportingService` реализуйте `build_many(currencies)` — словарь `{currency: Report}` с единственным вызовом `build()` для каждой уникальной валюты. `approved_totals(currencies)` возвращает словарь `{currency: approved_total}` на основе готовых отчётов. Сервис сам не фильтрует записи.

## Примеры и границы

- Контрольный построитель возвращает `Report('Контроль', EUR, ())`; вызывающий код получает именно этот отчёт.
- Разные реализации независимы; второй отчёт не содержит строк первого.
- Ошибка не меняет хранилище; повторный расчёт не создаёт новые `TransactionRecord`.
- Готовая проверка отклоняет обычный список вместо `Report`.

Последовательности и конфигурации дополнительно проверяются в `tests/test_progression.py`. Прочитайте ожидаемый результат каждого сценария до реализации.

Все проверки открыты: `tests/test_contract.py` и `tests/test_review_contract.py`.
Описание объектов — в [REFERENCE.md](REFERENCE.md), исходные результаты тестов — в [STARTER-STATE.md](STARTER-STATE.md).
